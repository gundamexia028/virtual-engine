# SCENARIO_BEHAVIOR_CONTRACT.md

## 1. 文档目的

本文件定义V1.3.8模块化重构必须保持的行为基线。

本契约用于约束后续代码搬移、模块拆分和接口提取，不用于改变医学内容、评分规则、病例脚本、页面流程、存储格式或权限范围。

* 黄金JSON快照：`app/tests/golden/v1_3_8_behavior_baseline.json`
* 原有回归测试：`app/tests/`

## 2. 当前场景模型

当前4份场景脚本不是显式的“节点—选项—目标节点”图，而是以下状态机：

`baseline隐式起点 → actions动作选择 → dynamics状态变化 → end_conditions结束判定`

因此，当前契约中的对应关系为：

| 通用概念 | 当前V1.3.8实现 |
|---|---|
| 起始节点 | `baseline`隐式起点 |
| 节点状态 | `Simulator.state`中的时间、生命体征、症状、flags和grade |
| 选项 | `actions`中的动作 |
| 节点推进 | `Simulator.apply_action`或剂量方法后执行`Simulator.tick` |
| 分支条件 | Python动作分支及`dynamics.rules[].when` |
| 终止节点 | `end_conditions`和`Simulator.is_done`产生的完成状态 |

证据：

* `app/peds_anaphylaxis_sim/engine.py:81` `Simulator.__init__`
* `app/peds_anaphylaxis_sim/engine.py:373` `apply_effects`
* `app/peds_anaphylaxis_sim/engine.py:464` `tick`
* `app/peds_anaphylaxis_sim/engine.py:1272` `apply_action`
* `app/peds_anaphylaxis_sim/engine.py:1966` `is_done`

后续如引入显式节点模型，必须通过节点ID、选项ID、目标引用、可达性、终止节点和循环契约；不得把现有4份脚本伪装成已经具有显式节点结构。

* 4组成功、失败和超时结束条件。

### 3.2 黄金路径

黄金基线覆盖4类流程，每类包含理想、典型错误和关键分支3条路径，共12条：

| 流程 | 脚本 | 模式 | 路径 |
|---|---|---|---|
| 临床训练 | 临床初始版 | `coach` | 理想、继续输注错误、拔除后重建静脉通路 |
| 临床考核 | 临床变体版 | `exam` | 理想、继续输注错误、拔除后重建静脉通路 |
| 学院训练 | 学院基础版 | `coach` | 理想、仅旁观错误、护生独立给药角色边界风险 |
| 学院考核 | 学院变体版 | `exam` | 理想、仅旁观错误、护生独立给药角色边界风险 |

每条快照固定记录：

* 隐式节点和动作序列；
* 关键选择；
* 总分、原始分、扣分和各评分维度；
* 最终生命体征、症状、分级和病情状态；
* 完成状态与结束原因；
* 关键反馈、缺失项和流程安全问题；
* 结果页核心字段。

## 4. 场景加载契约

必须保持：

1. JSON使用UTF-8读取。
2. `schema_version`当前为`1`。
3. `scenario.id`、`scenario.script_role`和动作ID决定当前场景身份及调用。
4. `baseline`完整初始化患者时间、生命体征、症状和flags。
5. `coach`和`exam`继续是当前合法模拟模式。
6. 当前4份场景文件内容和SHA-256不得因工程重构而改变。

可以等价重构：

* 将读取、解析、校验和目录发现移到独立加载器；
* 用不可变对象表达加载结果；
* 增加明确的场景manifest。

允许扩展：

* 在保持旧脚本兼容的前提下增加显式节点schema；
* 按`scenario_id + phase`定位脚本；
* 增加新的场景版本校验器。

## 5. 节点推进与分支契约

必须保持：

1. 相同场景、模式、固定随机种子和动作顺序产生相同状态推进。
2. 动作首次执行时间和有效完成时间语义不变。
3. 动作后时间推进、动态规则触发顺序和生理边界处理不变。
4. 未知动作继续被安全记录，不得执行任意代码或静默视为有效动作。
5. 临床与学院专用动作的角色边界和后果不变。

可以等价重构：

* 将动作分派拆为注册式处理器；
* 将动态规则执行移到分支引擎；
* 将状态推进从Streamlit页面适配层移出。

允许扩展：

* 新动作处理器；
* 显式节点和目标节点；
* 经审核的循环分支声明。

显式节点扩展必须满足：

* 场景ID、节点ID和选项ID唯一；
* 起始节点存在；
* 所有目标节点存在；
* 不存在不可达孤立节点；
* 至少有一个可达终止节点；
* 循环必须逐边明确声明。

## 6. 正误反馈契约

## 7. 分数累计契约

不可改变的医学与评分行为：

1. 当前场景声明总分均为100分。
2. 相同动作顺序和时机必须获得相同原始分、扣分、显示总分和维度分。
3. 单次计分、首次选择、有效完成时间和延迟规则语义不变。
4. 临床5个评分模块和学院6个评分模块的边界、满分和汇总结果不变。
5. 学院安全扣分与临床补救得分的现有语义不变。

可以等价重构：

* 将评分事件、维度汇总和显示分计算提取到评分引擎；
* 以只读评分结果对象替代散落字典；
* 保持`build_report`输出一致的前提下重组内部函数。

不得在模块搬移中顺便调整分值、时限、扣分或完成门槛。

## 11. 会话恢复契约

必须保持：

1. 临床训练、临床考核、学院训练和学院考核均可恢复。
2. 恢复内容包括模式、阶段、场景、模拟器状态、选择、评分、反馈和完成状态。
3. 随机恢复标识不可预测，并绑定当前客户端特征。
4. 无效、损坏、过期或绑定不匹配的草稿安全失败。
5. 完成、主动重置或退出时按现有规则清理草稿。
6. 草稿不得包含访问码、管理员密码、Secrets或管理员授权上下文。
7. 当前快照`schema_version = 1`兼容性保持不变。

可以等价重构：

* 将快照序列化、文件存储和Streamlit状态适配分层；
* 在保持旧快照兼容的前提下增加新版本读取器。

## 12. 问卷衔接契约

## 13. 幂等保存契约

必须保持：

1. 同一完成标识最多保存一条训练结果。
2. 同一问卷提交标识最多保存一条问卷结果。

4. JSONL写入继续使用锁和原子追加保护。
5. 损坏行被隔离记录，不得破坏已有合法记录。
6. 保存内容不得包含访问码、管理员密码或Secrets。

可以等价重构：

* 将本地JSONL和Supabase实现统一到Repository接口；
* 将幂等键、锁和损坏行处理移到存储层。

## 16. 黄金快照更新规则

黄金快照不是普通期望值文件，不得因测试失败直接覆盖。

允许更新前必须同时满足：

1. 明确说明行为变化原因；
2. 区分工程等价变化和业务行为变化；
3. 医学或评分变化已获得相应确认；
4. 对比旧、新快照并逐项审核；
5. 确认不存在时间戳、随机ID、会话标识、本机路径或Secrets；
6. 在变更记录中注明快照更新范围；
7. 独立审查通过。

未经上述审核，快照差异应视为回归失败。

1. 原有139项测试全部通过；
