# 部署、数据保护与回退

**当前不可直接部署。本文件是验收通过之后的操作说明，本轮没有执行任何线上变更。**
固定目标：`gundamexia028/virtual-engine`；分支`review-deploy`；入口`app/streamlit_app.py`。禁止操作`peds-anaphylaxis-simulation`。

## 1. 发布前必须关闭的门禁

真实依赖环境中全部16个既有脚本和新增回归通过；不带Streamlit替身。有限矩阵/边界回归通过。真实浏览器脚本限定范围通过并保留trace/截图；用户报告的刷新、连续操作、模式切换以及输入面板开闭场景必须实测。补做完整注册、成绩保存/下载、问卷、管理权限、刷新恢复与目标Safari浏览器检查。
临床/教学负责人确认实际给药配合角色边界、病程转移、关键顺序、扣分和临床理想路径内容。若用于研究采集，记录版本变更及评分不可直接混用的处理。
保存实际安装依赖清单和运行平台，锁定通过验收的组合。本轮没有真实runtime锁、未验证线上环境兼容性。

## 2. 隔离本地启动

从完整源码ZIP解压，不与旧运行目录混合。先建虚拟环境并按复跑说明安装。使用新的数据及草稿目录，不填生产Supabase地址或密钥。示例在候选仓库根目录：

```bash
export APP_MODE=production
export PEDSIM_RESULTS_DIR="$PWD/audit_results/manual/runs"
export PEDSIM_DRAFTS_DIR="$PWD/audit_results/manual/drafts"
export SUPABASE_URL=""
export SUPABASE_KEY=""
export SUPABASE_ANON_KEY=""
export SUPABASE_SERVICE_ROLE_KEY=""
# 设置新生成的测试 APP_ACCESS_CODE、ADMIN_PASSWORD、AUTH_CONTEXT_SIGNING_KEY；不使用生产值。
python -m streamlit run app/streamlit_app.py --server.address 127.0.0.1
```

密码/签名键通过本地环境或未入库的secrets配置提供；不要粘贴进报告，不要提交真实 `secrets.toml`。机构权限需要时使用专门合成机构配置，不复制生产配置。例子仅启动local，不是发布命令。

## 3. 真实部署前先保留远端现状

本次上传源码并不自动等于发布时当前线上版本。发布执行者必须记录实际远端commit、当前分支、部署Python/依赖、环境变量名称与安全保管的值、数据目录、存储后端，以及当前应用配置。
备份代码和配置；结果索引、完整报告、问卷、机构访问配置、草稿分开备份。对文件备份记录大小和SHA；对云存储使用其合适的备份方式。不要把数据或密钥放进待推送源码ZIP。
源码替换只应进入目标仓库的独立本地工作分支。先检查remote、分支和工作区差异，禁止自动强推、禁止`git clean`清理数据、禁止复制覆盖其他仓库。审核后才由有权限者将候选合入`review-deploy`。
本交付不包含自动`git push`或云端发布脚本，以避免未验收候选意外更新自动部署分支。

## 4. 新旧会话/成绩兼容性

新版引擎增加版本和有效完成时间约束。**旧版未完成草稿不兼容；不能强行恢复或改版本号绕过校验。** 发布前结束/暂停旧课程，明确通知重新开始新会话。旧草稿归档隔离，避免新运行清理逻辑触及备份。
旧已完成报告保存原始内容和原版分数，不用新版重算并覆盖。新增报告记录新版引擎标识；新旧评分、乱序扣分和成功门槛不同，统计分析时分层处理。不能无说明混入原有已冻结研究数据。
本轮没有创建数据库模式迁移，也没有执行历史成绩迁移。真实存储后端写入兼容性尚未在线验证，不能因此声称数据库自动兼容。

## 5. 发布后检查与回退触发

使用合成测试账号核验两体系、6阶段、规范结束、典型乱序、剂量拒绝、页面完整性、成绩/问卷唯一保存和读取顺序。不能使用真实患儿或学生结果做可丢弃试写。
发生页面无法完整呈现、错误满分/成功、剂量异常被接收、重复保存、权限越界、旧数据不可读或频繁恢复失败时，暂停新会话并回退；保留错误日志与失败版本证据，不直接清空数据“解决”。

## 6. 回退步骤

首先停止新增会话/写入；备份候选版运行期间产生的新增结果、问卷和日志并标记引擎版本。随后恢复部署前确认的代码commit、对应依赖组合及配置，不只是恢复一个`engine.py`。
恢复旧版时使用旧版兼容草稿目录；新版草稿另行归档，不能让旧引擎读取。已完成的新结果保留，不因代码回退而删除，也不以旧分数重算。重新核验登录、两体系入口、历史结果读取和新旧记录可区分后，才恢复服务。
证据包附的原始ZIP只能恢复“本轮上传基线”，不保证它就是届时部署前的线上版本。因此真正回退优先使用发布前记录的实际线上commit及配置备份。

## 7. 应签署的记录

发布候选代码SHA/commit、Python及依赖解析清单、测试证据路径、临床/教学内容确认、数据备份位置、旧草稿处理、实际目标仓库/分支/入口、发布与回退责任人、最终发布或HOLD决定。未完成任一必要验收，不得把本轮HOLD改写为通过。
